# ML Eval Forge

Reproducible machine-learning engineering tasks for training, inference, calibration, and verification.

ML Eval Forge is a small, dependency-light evaluation lab built around synthetic multispectral-style data. It is designed to make the engineering contract visible: the data split is fingerprinted, the model is trained deterministically, calibration uses validation data only, metrics are computed from held-out predictions, and a validator checks the run before its report is accepted.

## Why this repository exists

Many ML failures are not caused by a missing model layer. They come from data leakage, non-reproducible splits, invalid probabilities, calibration fitted on the test set, silent numerical errors, or performance claims without a measurement protocol. This repository turns those failure modes into executable checks.

## Included projects

### 1. Calibrated classification task

`ml-eval-forge run` generates a deterministic binary classification dataset, fits a regularized logistic model with NumPy, fits a scalar temperature on validation logits, evaluates the untouched test split, and writes machine-readable evidence.

The report includes accuracy, precision, recall, F1, log loss, Brier score, expected calibration error, and a deterministic bootstrap interval for accuracy.

### 2. Inference parity and performance lab

`ml-eval-forge benchmark` compares vectorized batch inference with a deliberately simple row-wise reference implementation. It fails if outputs disagree beyond the configured tolerance and records latency, speedup, and maximum absolute error as JSON.

## Engineering signals

- Deterministic NumPy data generation and seeded optimization.
- Train/validation/test ownership checks and dataset fingerprinting.
- Validation-only temperature calibration; test data is not used for fitting.
- Finite-value, shape, probability-range, and numerical-parity contracts.
- Reproducible JSON artifacts suitable for review or downstream automation.
- Unit tests covering repeatability, metric behaviour, calibration, and rejection paths.
- GitHub Actions CI on a clean Python environment.
- No hosted model, private data, or GPU required.

## Quick start

```bash
python -m venv .venv
# Windows PowerShell: .venv\\Scripts\\Activate.ps1
python -m pip install -e .

python -m ml_eval_forge run --output results/latest
python -m ml_eval_forge benchmark --output results/latest/benchmark.json
python -m ml_eval_forge validate --run results/latest
python -m unittest discover -s tests -v
```

The only runtime dependency is NumPy. The commands are intentionally explicit so that a reviewer can reproduce the evidence from a fresh checkout.

## Example evidence

The committed files under `results/latest/` are generated by the commands above. Values are measurements from the included synthetic workload, not claims about a production dataset.

```text
test accuracy:       0.773
test F1:             0.775
test ECE:            0.0508 raw / 0.0514 calibrated
parity max error:    <= 1e-12
```

Calibration is fitted on the validation split only; this seed is retained as-is, including the small ECE movement, rather than selecting a flattering run. Run the benchmark on your machine before comparing latency. Hardware, BLAS, Python, and NumPy versions affect the result.

## Layout

```text
src/ml_eval_forge/
  data.py          deterministic data and split fingerprints
  model.py         regularized logistic model and stable loss functions
  metrics.py       classification and calibration metrics
  harness.py       experiment orchestration and validation contract
  benchmark.py     reference-vs-vectorized inference measurement
  cli.py           reproducible command-line interface
tests/             deterministic regression and failure-path tests
results/latest/    small JSON artifacts from the included workload
```

## Limitations

The dataset is synthetic and the model is intentionally small. This repository demonstrates evaluation and systems discipline; it does not claim domain accuracy on satellite imagery, production serving throughput, or GPU performance. For large-image inference and spatial parity, see [tileflow-inference](https://github.com/dimxxkun/tileflow-inference). For a real-image training and calibration workflow, see [geovision-bench](https://github.com/dimxxkun/geovision-bench).
